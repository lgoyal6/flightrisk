# Contributing to flightrisk

Thanks for looking. flightrisk is a signal system rather than an analysis, so the useful
contributions are new candidate signals and harder skepticism checks, not tuning.

## The contract you must not break

**Every feature at quarter T uses only what was observable at T.** A model that peeks is
not a worse model, it is a fake result, and the whole repo exists to make that
impossible to do quietly. `audit.asof_audit()` rebuilds every feature from a panel
truncated at each cutoff and demands the values at T be identical to the full-panel
values; it raises `AsOfViolation` on any mismatch and runs on every `flightrisk build`.
`audit.shuffled_label_check()` permutes labels *within* quarter and `pipeline.run_backtest`
raises `AssertionError` if lift does not collapse to baseline. If a change of yours makes
either fail, the change is wrong, not the harness.

Corollaries worth stating, because they are easy to violate by accident:

- The label at T describes T+1, so training stops at T-1. `tests/test_backtest.py` pins
  that boundary.
- Imputers and scalers are fitted inside each fold, through an sklearn `Pipeline`.
- Verdicts are applied by rule from ablation evidence. `INCREMENTAL_MIN = 0.05` and
  `STABILITY_MIN = 0.70` in `src/flightrisk/scorecards.py` were fixed in `PLAN.md` before
  any result was seen. Moving a threshold so a favourite signal graduates is the one
  thing that voids the whole exercise.
- The three `dumb_*` tripwire signals must stay KILLED. They are content-free by
  construction; if one survives, something upstream is broken.

## Getting oriented

| Path | What lives there |
|---|---|
| `PLAN.md` | The preregistered plan, including the thresholds. |
| `EXPERIMENTS.md` | Append-only log: hypothesis, result, decision, one entry per experiment. |
| `src/flightrisk/registry.py` | The signal registry. Single source of truth for candidates and verdicts. |
| `src/flightrisk/signals/` | One module per family: `funding.py`, `balance.py`, `controls.py`, `text.py`. |
| `src/flightrisk/audit.py` | As-of audit and the shuffled-label check. |
| `src/flightrisk/backtest.py` | Walk-forward folds, models, baselines. |
| `src/flightrisk/scorecards.py` | Graduation rules, and the generator for the README table. |
| `data/manual/` | The hand-adjudicated inputs: exclusions, EDGAR crosswalk, extraction labels. |
| `reports/` | Every generated number. Nothing here is typed by hand. |

## Building and testing

```bash
make setup                                   # uv venv + install with dev extras
export FLIGHTRISK_CONTACT=you@example.com    # SEC asks that you identify yourself

make test          # pytest
make lint          # ruff check + ruff format --check over src and tests
make all           # pull, build, backtest, falsify, scorecards, score, test
```

`make text` is deliberately outside `make all`: it fetches hundreds of documents from SEC
EDGAR and makes an LLM call per document. Both are cached, so a re-run is free and a first
run is not. There is no CI here, so `make test lint` locally is the only gate.

## What makes a good PR here

- One concern per PR, with a test that fails before and passes after.
- New signals go in through `@register` in `src/flightrisk/signals/`, with a one-line
  economic rationale, and a compute function that reads nothing later than T. Adding one
  is a one-function diff on purpose; let the graduation rules judge it.
- Never edit `reports/` or the README's signal table by hand. They are generated by
  `flightrisk scorecards`, between the `BEGIN:signal-table` markers. Regenerate instead.
- Every experiment gets an `EXPERIMENTS.md` entry in the existing format, including the
  ones that failed. The failures are the most useful part of that file.
- Claims about the FDIC API belong in `config.py` as a verified field, not an assumption.
  Unknown field names come back HTTP 200 with the column silently missing, which is why
  `data.py` validates against the published dictionary before the request.

## Good first areas

- **Register a candidate signal.** 35 are registered today across four families. A
  well-argued funding-structure or balance-sheet ratio that is genuinely as-of-T is the
  single most useful contribution, and the machinery will park or kill it honestly.
- **A second labeller for the extraction set.** `data/manual/extraction_validation.csv`
  holds 30 documents scored by one rater, and inter-rater reliability is the ceiling on
  those accuracy numbers. Re-scoring the same 30 blind would separate construct ambiguity
  from extractor error.
- **Adjudicate the extreme declines.** `reports/extreme_declines_review.csv` lists ten
  quarterly declines of 50% or worse. Silvergate and the crypto-adjacent names are
  genuine; the community-bank cases are unresolved and stay in the labels as noise.
  Confirmed structural cases belong in `data/manual/label_exclusions.csv` with a citation,
  in the format the existing six use.
- **Roll the panel forward.** `END_QUARTER` in `src/flightrisk/config.py` is pinned to
  `2026Q1`, the latest published Call Report at the time. Advancing it as FDIC publishes
  is bounded, recurring work.

## Conduct

Be decent. Disagree about the evidence, not about the person.
